# Changelog

## 0.2.0 — 2026-11-26

- **Coughs, sneezes and laughs that sound like it.** A line can be a vocal sound instead of words: `"sound": "cough"` (also `clearThroat`, `sneeze`, `snore`, `gulp`, `hiccup`, `gasp`, `sigh`, `yawn`, `giggle`, `laugh`, `sob`, `scream`, `hum`, `groan`), with `text` as the balloon writes it ("Achoo!"). The balloon of a sound is drawn differently (dashed, tilted, no highlight). Each engine makes it the way it can: ElevenLabs `eleven_v3` with its audio tags; VoxCPM2 asks the voice for a laugh or a sigh, but a cough asked of it came out as words, so the sounds without a voice in them are synthesised by the studio (`scripts/vocal-synth.mjs`, at the pitch heard in the character's reference clip); edge-tts gets the synthesised ones and a recording through `voices:import` for the rest. What each engine can do is in its `engine.json`, shared by its recorder and the check, and a series can choose otherwise per sound after listening (`"vocalSounds"` in `series.json`).
- **The minimum every voice engine must meet:** speech in the character's voice, the same voice all series long, and no two characters sharing one. `npm run check` now fails when two voices have the same description and seed, the same edge-tts voice or the same ElevenLabs voice id, and warns when two differ only by seed. Everything beyond that is what the engine can do, said before recording rather than discovered after.
- **The test panel.** `npm run voices -- --test [VOICE …] [sound …]` records each voice's sample sentence plainly and with two deliveries, and every vocal sound the way the engine makes it, into `out/voice-test/` for the Director to hear. Nothing in the series changes.
- **How a line is said.** `"delivery": "scared, urgent"` (a few English words, from the storyboard's expression) is given to VoxCPM2 as an instruction alongside its reference clip, so the voice stays the character's, and to ElevenLabs `eleven_v3` as audio tags. edge-tts ignores it, and the check says so.
- **Written for the ear.** `npm run check` warns about text a voice reads badly or aloud: digits, symbols, emoji, web addresses, abbreviations in capitals, and stage directions such as "(coughs)" or "*sigh*". Quality Control reviews lines for it, and the recipes tell the Writer.
- **A pronunciation dictionary per series.** `series/pronunciation.json` (`{"word": "how it is said"}`) is applied to every line without `say`, so a name the engine gets wrong is fixed once for every episode. The listening check accepts a take that matches either the text or how it was said.
- **Only changed lines are recorded again.** `npm run voices -- <ep>` used to record every line of the episode, replacing approved takes and spending ElevenLabs credits on lines that had not changed. What each line was recorded from (text, `say`, `fx`, `delivery`, `sound`, pronunciation, the voice) is kept in `src/audio-takes.json`; unchanged lines are kept. A named line is always recorded again, `--force` records them all, and a recording brought in with `voices:import` is replaced only when its line is named. Lines recorded before this are kept when what Whisper heard in them matches the script. `npm run check` warns about a line whose text or pronunciation changed after it was recorded.
- **Fewer automatic retakes.** Whisper still listens to every take (about 3 seconds a line), for the word highlight and to catch a broken take, but only a take with words missing or garbled (score below 0.5) is made again, and at most twice. A take that is only a little off is kept and marked `??` for the Director's ear instead of being retaken up to four times; `voices:check` says LISTEN or RETAKE.
- **Recording uses about half the memory.** A VoxCPM2 recording session peaked at 12.5 GB, mostly freed memory MLX kept for reuse. The voice scripts now hand it back at once (and record a little faster), and the listener is Whisper large-v3-turbo in 4 bits, which heard the same words as the full model in English and Indonesian tests: the same three lines now peak at about 6 GB. The 4-bit listener (about 0.5 GB) is downloaded on first use.
- **A voice from a real person's recording.** A character can speak in the voice of someone the Director recorded (with their consent): `"source": "recording"` in `voices.json`, the recording as the reference clip, and an optional `"prompt"`, a short clip with exactly what is said in it, so the engine carries on from the person's own words and keeps their accent (VoxCPM2's high-fidelity cloning; only an engine whose `engine.json` says `"recordings": true` takes one, VoxCPM2 today). A recorded voice is never generated or remade (`--ref` refuses), and changing its prompt records its lines again. It takes no instruction, so `delivery`, the spoken `fx` and voiced sounds do not apply to it: its coughs are synthesised and its laughs brought in, and `npm run check` warns about each such line. `/voices-voxcpm2` says how to ask for a good recording.
- **No voice engine is chosen for the Director.** A series without `"voiceEngine"` used to record with VoxCPM2 without anyone deciding it. Now nothing is recorded until the Director chooses (`voxcpm2`, `elevenlabs` or `edge`); `npm run voices`, `voices:setup` and `voices:check` say what each one is and when it is recommended (from its `engine.json`), `npm run check` and `npm run status` say none is chosen, and VoxCPM2 stays the recommendation on an Apple Silicon Mac.
- **Each voice engine is a package of its own; the studio names none.** Everything particular to an engine lives in its folder `skills/voices-<name>/`: `SKILL.md` (the crew's guide: setup, models and memory, how its voices are made, what it can do, its quirks and costs), `engine.json` (the Python and packages it needs, the platform, keys in `.env`, which listener it uses, how its voices are made, what each model can do, how each vocal sound is asked for, and how it is recommended) and `record.py` (its recorder). The studio finds the engines by their folders: `npm run voices` runs the series' recorder through the shared loop, and `check`, `doctor`, `status` and `voices:setup` read `engine.json` instead of knowing each engine, so a new engine is a new folder. The three are `voxcpm2` (the engine that was called `local`; series that say `"local"` keep working), `elevenlabs` and `edge`. The crew reads only the guide of its series; `/voices` keeps what holds for every engine, and `scripts/VOICES-SETUP.md` keeps the comparison the Director chooses from. The rules the studio carries out stay in code, so a guide that is not read changes nothing. The VoxCPM2 guide records what was learnt: memory, model sizes, where the models are kept, and that it can read Indonesian "c" as "k".
- **A pronunciation fix that belongs to one engine stays with it.** `series/pronunciation.<engine>.json` (for example `pronunciation.voxcpm2.json`) is used on top of `series/pronunciation.json` by that engine alone. A respelling that works around one engine's quirk, such as VoxCPM2 reading Indonesian "c" as "k", no longer follows the series to another engine, where it could make things worse. `npm run check` checks each file and warns about one named for an engine the studio does not have.
- **Which languages an engine speaks.** An engine's `engine.json` can list the languages each model speaks (`languages`, from the maker's own list: VoxCPM2's 30, ElevenLabs `eleven_v3`'s 74; edge-tts has its catalogue instead). `npm run check` warns when the series language is not among them, and the choice of engines says so before the Director picks one.
- **The studio core is the studio's own work and Remotion; every other tool is a skill.** What uses a model or an outside tool moved out of `scripts/` into a skill folder with its guide: the voice kit every engine shares (recording loop, voice check, setup, the synthesiser of coughs and sneezes) into `skills/voices/`; the listener into `skills/listen-whisper/` (Whisper, optional: without it takes are kept unchecked and word times estimated); the music synthesiser into `skills/music/`. `npm run voices`, `voices:check`, `voices:setup` and `music` work as before, and a series' own `series/music.mjs` needs no change. Raw takes now go to `out/.raw_voices/`.
- **No ffmpeg to install.** The studio uses the ffmpeg that comes with Remotion (`scripts/lib/ffmpeg.mjs`). Its build lacks the filters the studio used for trimming silence, the echo and joining the board, so those are now done in code: silence is trimmed at the same -45 dB (the same lengths to within about 10 ms), the echo is mixed in the voice kit, and the board is a small Remotion composition (`board-sheet`). `npm run doctor` no longer asks for ffmpeg.
- The three voice engines now share one recording loop (`scripts/voicelib.py`): every engine scores each take on the finished file, as VoxCPM2 already did.

## 0.1.5 — 2026-11-25

- **The board shows every shot.** `npm run still -- <ep> board` used to show 8 evenly spaced moments, so a short shot could be missed entirely. It now shows the start of every scene and every spoken line once its balloon is up (16 pictures for the sample, about 15 seconds), so a character cut off or a balloon over a face is seen before the Director watches. `board 12` still gives evenly spaced moments.
- **The first episode is reviewed too.** The proposal of a new series is written before the studio exists, so Quality Control never read the first episode. It now reads the draft proposal as a plain subagent before it is sent.
- **Changes after a screening have a path.** A change of words goes through QC (lines) and only the changed lines are recorded again; a change of picture is just fixed; a new voice means retaking that character's lines; then a fresh board and a screening of what changed, with a new preview link.
- **Specialists first, Quality Control last,** so QC reads the words as they will be shown.
- **Recording is quicker again.** Word times for the highlight come from the same listening pass that scores each take; only `echo` lines are listened to a second time.
- **Quality Control reviews the words, not the pictures.** Reviewing stills shot by shot made every episode slow. QC now reads the script, the storyboard and the lines before the Director sees them, and before recording: the Director's words kept, every formula beat there, lines short enough for a balloon, characters in voice, quotations marked not verified, `lines.json` matching the script with the right voices and ids. It never renders. The crew's look at the picture is one board of the whole episode, with a closer still only of a shot that looks wrong; motion and detail are the Director's in the preview.
- **The same letters on every machine.** On-screen text (balloons, captions, signs, review labels) used whatever rounded font the computer had, so a render on another machine could come out in a different face and wrap differently. The studio now ships its own typeface, Nunito (SIL Open Font License, from the `@fontsource/nunito` package), and Remotion waits for it before drawing a frame; nothing is fetched from the internet. Text in a script Nunito lacks (Arabic, Thai, Chinese, Japanese, Korean, …) still uses the computer's fonts. `FONT` now lives in `src/engine/font.ts`.
- **Each word lights up as it is spoken.** Balloons and narration captions mark the word being said, like a marker pen over it, so a video can be followed with the sound off. Whisper, which already listens back to every take, now also notes when each word is heard (`src/audio-words.json`, committed). When the words heard do not match the words shown one for one (no listener installed, `say` spelt differently, a recording brought in from elsewhere), the times are estimated from word lengths and punctuation. `npm run voices:check` fills in the word times of recordings made before this, and of imported ones. A series can turn it off with `"highlightWords": false`.
- **Mouths follow the voice.** A character given its lines (`talking={[m.hello, m.again]}`) opens its mouth with the loudness of the recording, frame by frame, and shuts it in the pauses between words; it used to flap at a steady beat whatever was said. Each scene reads its recordings (`@remotion/media-utils`) before its first frame is drawn. `talking={true}` still flaps, for something with no recording, and a line not recorded yet flaps until it is. A model character plays its talk animation while one of its lines plays.
- **Remotion's own guides for the crew.** `npm run remotion-guides` (run during setup, after `npm install`) downloads four of Remotion's official agent guides from `remotion-dev/skills` into the studio's `skills/`: writing markup (animation, timing, audio, 3D, text), captions, searching the Remotion docs, and reading media files. The crew reads them when it writes Remotion code. The guides that would create a new project, start the preview, render or upgrade packages are left out, and `CLAUDE.md` says the studio's own commands and rules win where the guides differ. They are Remotion's (Remotion license), so each studio downloads them at a fixed version and never commits them; nothing downloaded is run. `npm run doctor` says whether they are there. `CLAUDE.md` also says that nothing is fetched from a URL, since some guides play sounds from `remotion.media`.
- **Arabic reads right to left, in its own font.** A balloon or caption whose words are mostly Arabic or Hebrew is laid out right to left (counted by words, so a line that opens with a Latin name still reads right): the full stop and question mark land on the correct side, and the word highlight moves the right way. Arabic script is drawn in Noto Sans Arabic (SIL Open Font License, `@fontsource/noto-sans-arabic`), shipped with the studio like Nunito, so vowel marks and joined letters look the same on every machine. The balloon width estimate no longer counts vowel marks as letters.
- **2D pieces: a closing card and a toolbox.** `MessageCard` shows one line on a full-frame card: the advice or moral at the end, a lesson, a quotation. The line is read by its voice with each word lit, an optional heading rises word by word, and soft sparkles drift behind. A narration line said with `t.say(id, {caption: false})` is not shown again as a caption. The sample episode now ends on one (42.0 s). The studio adds [remotion-bits](https://github.com/av/remotion-bits) (MIT) for other flat pieces in any look, and as the start of a 2D look: animated text, typewriter, counters, particles, gradient transitions. It is made to share the studio's three.js, and `culori`, which it needs but does not list, is installed with it.
- **Lines that draw themselves.** The studio adds `@remotion/paths`: lines that draw themselves (`evolvePath`), shapes that morph, things that travel along a path. The closing card uses it for a wavy line under its heading.
- Fixed while reviewing the above: the balloon width estimate counts the vowel signs of Hindi, Bengali, Tamil and similar scripts again (only marks that sit on a letter take no room); a recording's length is saved before its words are timed, and a failed timing no longer stops the recording; Thai, Lao, Khmer and Myanmar lines light up word by word (their words are found with the browser's word dictionary); `npm run remotion-guides` gives up after a minute on a stalled network; the crew is told to skip a guide's reference to a Remotion skill that is not installed; the sample's closing line is `e1_s3_end_n`, matching the scene it is in.

## 0.1.4 — 2026-11-24

- **Killing the preview server stops it for good.** The keeper used to start Remotion Studio again whenever it ended, so a server stopped from outside came straight back. It now restarts only a studio that quit by itself; one stopped by a signal stays stopped, and the keeper ends with it.

## 0.1.3 — 2026-11-24

- **The preview belongs to the session.** It stops by itself when the agent session that started it ends, instead of running on after the app is closed. `npm run preview -- --attached` runs it inside the command, so a session can start it as a background task: it is then listed among the session's tasks and can be stopped there.

## 0.1.2 — 2026-11-24

- **The crew asks before it proposes characters and setting.** After the story, the Director is asked who the characters are and what the setting is like, in one message. "You choose" is a full answer, for one or both, and only then does the crew propose them. Scenes and lines are still written by the crew for approval.
- **Who writes what, said plainly.** The Director gives the idea and decides; the crew writes the scenes and lines and proposes characters and places for approval. The Director never has to write a script, and what they do give in detail is binding.
- **Specialists on the crew (`/new-agent`).** The Director can add a subagent of their own to a series: someone who checks or advises on something the series must get right, against sources the Director names, at the stages the Director chooses. Specialists are listed in `series/crew.json`, checked by `npm run check`, shown by `npm run status`, and consulted before their stage reaches the Director. The crew does not think specialists up, but offers one, once, when the Director's own words bring in something that must match the world outside the series (quoted real texts, claims of fact, the rules of a field or faith, real people or events). A specialist that checks verifies only against a source it has opened, gives one of three verdicts (confirmed, wrong, not verified), and never edits the work; one that advises reports an opinion; one that does a job writes only the files of that job. The crew never thinks specialists up, but offers one, once, when the Director's own words call for it: they bring in something that must match the world outside the series, or they ask for a job to be set apart.
- **A new studio starts empty.** `setup-studio.mjs` no longer leaves the sample series in a new studio (`--sample` keeps it, for looking at in a separate folder). The crew used to read the sample before clearing it and carried its ideas into the Director's series.
- **The instructions carry no story of their own.** The front-door skill is rewritten around six principles (the series is the Director's, start from nothing, an okay is explicit, say what is happening, plain words, their language). Story-like examples are gone from the skill, the studio rules, the recipes and the Director's Guide; the example scene is a pattern with no content (two unnamed cast members and a grey box). The crew is told to take no name, character, place, object, plot or line from any example.
- **Episode formula.** A series may have fixed beats that every episode follows. Which beats is entirely the Director's; the skill carries no example formula. The Director gives it, optionally, in the brief; it is kept in the bible and every episode's brief and script are written to it beat by beat. The crew never invents one. A beat that quotes a real text (scripture, a hadith, a named person) needs the exact words and source from the Director: the crew does not write such quotations from memory.
- **The Director's characters, places and scenes are binding, and optional to give.** The brief now offers them as optional items next to the story. What the Director describes is used as described, and the crew may not add a character or a place on its own; what is left open the crew proposes, marked as its own, for approval before anything is built.

## 0.1.1 — 2026-11-24

- **The brief comes first.** Started with no idea given, the crew invented a whole show and first episode from the folder's name. Nothing is now proposed, installed or built until the Director has given the story and where it will be posted; length (about 30 seconds), language (the prompt's, else the Director's own) and pace have defaults. The fast track is the default pace, step by step on request, and the first proposal carries the plan of the first episode.
- **An answer is not an okay.** In a real first session the crew asked two questions, offered "just say okay", and took the reply "pake bahasa indo" as the go-ahead for setting up. The rules now say what counts as an okay, forbid mixing questions with "just say okay", and have the crew say before a long stretch of work what is and is not being made.
- **The crew no longer opens in English by default.** Started by its command alone, with no message to read, it answered an Indonesian Director in English. It now looks at the folder name and the computer's languages and region first, and inside a studio it uses the language of the series.
- **Fast track.** A Director who wants a finished video rather than nine approvals says "fast track" or "just make it": the first meeting becomes one proposal with one okay (which can carry the plan of the first episode too), and each episode stops twice (the whole plan in one message, then the finished picture). Tried twice by a fresh session on a one-sentence idea: first an 18-second vertical video with three stops, then, after its eleven reported unclear instructions were fixed, a 17-second one with two stops in five minutes (when the voice engine is set up, who makes reference clips, the language of voice descriptions, where the cover picture goes, what to do without subagents). `"pace": "fast"` in `series.json` records it, `npm run status` reports it, and installs, paid services and changes to approved work still ask on their own. Step by step stays the default.
- **Vertical video (1080×1920) is usable.** On-screen text follows the long side of the frame, so balloons and captions are readable on a phone instead of 56% of their landscape size; a balloon slides back inside the frame instead of hanging over an edge (in any format); captions sit above the bottom fifth of a vertical frame. `frameShot([...])` works out a shot that shows a group of characters whole in whatever shape the frame has, keeps room above the heads for the balloon, and in a tall frame lifts the group so the bottom is not empty ground, and `CLAUDE.md` and the episode recipe say how to frame shots for a tall picture.
- **A scene can change its music mood part-way:** `t.mood('calm')` in the script (or `t.mood(null)` for silence). It used to take a new scene. Music fades no longer break on a stretch shorter than 50 frames.
- **A scene can move something that stands on the map:** `<World replace={{tree: …}} />` draws that scene's own version of one place (a tree that shakes, a door that opens) without changing the map.
- New pose `pointUp`, for pointing at something overhead; `point` only ever pointed straight ahead.
- **Recording scores the finished file, not the raw take.** Trimming and levelling could clip a word, so `npm run voices` passed a line at 1.00 that `npm run voices:check` then flagged at 0.80. Both now listen to the same file; the line that showed it took three takes instead of one and passes both.
- A complete example scene ships with the episode recipe (`skills/new-episode/scene-example.md`): script, camera cuts, balloons, a change of mood and a prop drawn by the scene. An emptied studio used to have no scene left to learn from.
- Balloons with several rows spread their text evenly instead of leaving one word on the last row.
- `npm run still -- ep01 board`: the whole episode in one picture, 8 moments side by side (or `board 12`), from a single render. The quickest first look for QC and for the Director.
- **Ready to post.** After a final render the crew offers a cover picture and a `out/<ep>-<title>.post.md` with title, caption and tags in the series language.
- `npm run preview`: makes sure the preview (Remotion Studio) is running in the background and prints its links; a preview that is already up is reused, it starts itself again if Remotion Studio quits (it did once during a trial; killing it on purpose brings it back within two seconds), and `npm run preview -- stop` ends it. `npm run status` says whether it is running and where. Every request for a review now carries the link from this command (rule 6 on set, and the screening, episode, character and place recipes), so the Director is never told to start the preview themselves.
- Found by making a new series end to end ("Sari & Bimo", Indonesian, local voices):
  - `npm run voices:setup` also looks for Python in Homebrew and in uv, not only on the PATH; it used to say Python 3.12 was not installed when it was.
  - `npm run status` counts a render as an episode's only when the file is named after its story file, so the sample's leftover video is no longer reported as the new episode 1; `lessons.md` is no longer listed as if it had a stage.
  - `npm run clear-sample -- --yes` leaves an empty `series/story/world.md`, which the recipes read.
  - The map picture puts its title at the bottom, where place labels at the north edge no longer cover it.
  - The voices recipe says that test lines for a new voice are real lines of an approved script.
- Setting up the studio is one command (`scripts/setup-studio.mjs` in the skill): it copies the template, adds `TECH-STACK.md` and makes the links, never overwrites existing files, leaves out local leftovers (`node_modules`, `out`, voice environments, `.env`), and falls back to junctions or copies where Windows does not allow links.
- `npm run doctor`: what the computer and the folder have and what is missing (Node.js, ffmpeg, Chrome, packages, voice engine, API key present or not), with the command that installs each. Runs before `npm install`.
- `npm run status`: where the production stands, read from the folder: each story file's Status line, lines recorded per episode, what is registered and rendered. The crew starts from it when work is picked up again.
- `npm run still` takes a list of frames (`ep01 2 0,60,120`) and renders them in one go.
- `npm run clear-sample -- --keep` starts from the sample instead of emptying it, so `series.json` is no longer edited by hand.
- First meeting: the voice choice is written to `series.json` after the studio exists (it was asked for before the file was there), and is laid out as a table.
- Scripts share `scripts/lib/` (series folder, voice environment, Chrome search) instead of each reading the files its own way; an unknown `voiceEngine` now says which names are allowed.
- `/new-character` now also draws a character from a 3D model file: the order of work, and a table of what to do when one does not show, is the wrong size or will not render.
- A line with no recording no longer breaks a render: it plays as silence, as `check` always said.
- Optional characters from `.glb` models (`series/models.json`, `model` on a cast member): loaded before the picture is drawn, animation by frame number, checked by `npm run check`; model files are never committed. Review sheets for them: `sheet <id> poses` and `sheet <id> clips` show each animation part-way through.
- Character detail in the 3D look: sneakers with soles and toe caps, thumbs, sleeve cuffs, hem and neckline trims, shorts cuffs, and opt-in `nose` and `bigEars` (also `shoeSole`).
- Last-resort voice engine `edge-tts` (`"voiceEngine": "edge"`): free, no account, unofficial.
- `series/story/lessons.md`: the crew records what went wrong and how to avoid it, and reads it before every stage.
- `REMOTION_BROWSER_EXECUTABLE` and more Chromium locations for Linux; scripts no longer depend on `npx`, which could not start on Windows.
- Voice engine choice: ElevenLabs for Windows, Linux and Intel Macs (`"voiceEngine": "elevenlabs"`), and `npm run voices:import` for recordings from any source.
- The crew installs missing prerequisites itself (after one okay), asks the voice engine at the first meeting, and sets it up with `npm run voices:setup`.
- Getting started guide (`docs/getting-started.md`).
- Dependencies pinned to exact versions.
- Engine unit tests (`npm test`) and GitHub Actions CI.
- CONTRIBUTING guide and issue templates.
